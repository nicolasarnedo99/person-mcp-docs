person-mcp is an MCP server that remembers people for your AI agent. You read
a LinkedIn or X profile in your own browser, your agent extracts what you saw,
and person-mcp stores it. Before a call, an interview or an outreach message,
your agent asks it what you already know about that person and gets the career
history, links and every dated note back in one answer.

## Who it is for

You will get the most from person-mcp if you:

- meet a lot of people for work (developer relations, sales, recruiting, job
  searching) and lose track of what you learned about each one
- already work with an MCP client such as Claude Code, Cursor or Codex
- want that memory on your own machine, not in a third-party CRM

## How it works

person-mcp is a small TypeScript server built with
[mcp-use](https://mcp-use.com). It exposes five tools over HTTP and keeps
every record in a single `people.json` file next to the server.

| Tool | Kind | What it does |
| --- | --- | --- |
| `search-people` | read | Finds contacts by text across name, company, role and notes |
| `get-person` | read | Returns one contact's full record |
| `list-tracked` | read | Lists the contacts you flagged to keep an eye on |
| `import-person` | write | Creates or merges a contact; fields update, notes append |
| `log-interaction` | write | Adds a dated touchpoint, such as a message sent or a reply |

The server never contacts LinkedIn or X. Import is always started by a person
who opened the profile normally, so everything person-mcp serves is something
you chose to keep. The real `people.json` is gitignored, because it holds
private information about real people.
